# Source throughput upgrade

User authorized autonomous efficiency improvements and cloud publication; existing
verification and privacy gates remain unchanged.

Chosen approach: route installed AV, home automation, repairs and industrial
suppliers later, retaining every candidate; portable product plus channel clues
override the new routing penalty. Provider clues never become verified evidence,
ICP or exclusion reasons. Existing cached-source ordering and history locks remain.

Emit an execution contract for at most four independent read-only source requests
per group. Compact product, buyer-role and public-contact evidence instead of full
navigation output. An explicit primary-source failure is persisted once; only a
metadata-only result permits one focused read. No parallel compose/send/browser
writes. Ready qualified customers do not wait for an entire research batch.

Alternatives: increasing email concurrency is rejected because uncertain outcomes
would risk duplicate sends; enlarging packets beyond twenty would increase token
context without addressing source-read quality. Existing twenty-row packets stay.

Verification: routing preservation, channel override, five bounded groups for
twenty distinct sources, permanent group and unknown-send locks, regression tests.
This is an execution plan, not a background browser runner. No end-to-end speed
guarantee is claimed; live reads, region checks and sends still require the executor.
